# 周期与限额

套餐额度从多个时间维度约束用量，维度之间**同时生效、独立计算**——任一维度耗尽即拒绝请求（`QUOTA_EXCEEDED`，HTTP 402），直到该维度恢复。

## 限额维度

| 维度 | 含义 | 重置方式 |
| --- | --- | --- |
| 滚动 5 小时限额（rolling_5h） | 任意连续 5 小时窗口内的总额度 | 滚动窗口，最早用量滑出 5 小时后自动释放 |
| 每周限额（weekly） | 自然周内总额度 | 周切换时重置 |
| 周期限额（cycle） | 一个计费周期内总额度 | 周期切换时重置 |
| 总限额（total） | 套餐累计总额度 | 不重置，用完即止 |
| Token 总量（token_limit） | Token 套餐专属：累计 token 数 | 不重置，随用量递减 |

不同套餐启用的维度不同：订阅制套餐通常配置周期 + 每周 + 滚动 5h 三层；永久套餐通常只配总限额；Token 套餐只看 token 总量。具体额度以[套餐页](https://tokenmp.cn/plans)展示为准。

## 周期怎么算

计费周期的**锚点**是「激活时间与窗口重置点中较晚者」，周期长度由套餐配置（`cycle_days`，缺省用 `default_duration_days`）：

```
周期起点 = max(套餐激活时间, 上次窗口重置点)
周期长度 = cycle_days 天（订阅套餐常见 31 天）
```

- 订阅制（month 分组）：周期届满时周期 / 每周两个维度重置，滚动 5h 不受影响；套餐到期（`expires_at`）后整体失效。
- 永久套餐：周期长度按极大值配置（等效无周期），只看总限额递减。

## 超限时的表现

- 返回 `402 QUOTA_EXCEEDED`，提示当前套餐或余额不足（见[错误码表](/api/endpoints#错误码)）。
- 滚动 5h 超限：无需操作，最早的用量滑出窗口后自动恢复。
- 周期 / 每周超限：等窗口切换，或升级 / 兑换新套餐立即恢复。
- 总量 / Token 超限：需要兑换或购买新的量。

## 实用建议

- 跑批任务注意滚动 5h 窗口：短时间集中消耗容易触顶，可错峰拆分。
- 多套餐用户建议把「最近到期优先」留在策略前列，避免快过期的额度浪费。
- 给不同业务用独立 API Key，便于分别核对用量。
